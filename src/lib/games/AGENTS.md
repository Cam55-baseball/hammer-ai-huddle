- Live game-report sources exclude deleted games and scope to the signed-in athlete; frozen snapshots stay unchanged. Why: removed games must not feed new reports.
- Pitch intent/contact annotations use dedicated nullable pitch-ledger fields, never movement measurements or parsed historical notes; hard contact is an observation, not a measured threshold. Why: structured facts must not invent measurements.
- Imports map only exact known result aliases to ledger codes; unknown outcomes stay null with raw text in notes, and speed/angle never invent contact quality. Why: imported facts must remain queryable without guessed outcomes.
- Defense and running forms require only position/event choice; optional observations use explicit unknown/yes/no values and shared payload normalization. Why: untouched controls must never record invented outcomes, hands, innings or bases.

- At-bat writers require an explicitly entered inning/result and normalize optional facts through atBatEntryPayload; empty pitch lists never overwrite a manually entered or unknown count. Why: prior innings, probable opponents and empty lists are not evidence for this at-bat.
- Post-game reports count only entered facts: blank pitch types, counts and run results show "Not entered" and leave denominators; rates under MIN_TREND_SAMPLE are an "early read" and never drive Train next. Why: reports must never fill in what nobody logged.
- Team post-game report (/coach/team-report) reads linked players games via existing is_coach_of read policies and lists every entry source; blank results never count. Why: coach sees only permitted, entered facts.
- Team reports count canonical at-bat result codes and preserve unentered optional totals; observations never certify mechanics or author plan advice. Why: app-entered facts and absence of observations cannot justify invented results or training decisions.
- Aggregate steal-success displays use baserunningSummary and recordedRate, counting only explicit boolean outcomes; sample labels use entered-result counts. Why: unknown outcomes are not failures or evidence.
- Legacy baserunning split-view success percentages stay suppressed until their known-result denominator and live-game scope are certified; live GameReports event reads join nondeleted games. Why: aggregate totals cannot establish outcomes or revive removed games.
- Game IQ player reports, tap-in heat maps and the matchup planner live only in `gameIq.ts` (rendered by `GameIqReports` on the Game IQ tab), reading live nondeleted game rows; heat maps count only tapped zones, never snapshot scores. Why: one source from entered facts.
