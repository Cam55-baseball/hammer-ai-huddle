# Hammers Modality LLC — Data Inventory

**Scope:** this document describes what the Hammers Modality app (React + Supabase/Lovable Cloud) actually collects, stores, and sends to outside services, as found in `src/`, `supabase/functions/`, `supabase/migrations/`, and `src/integrations/supabase/types.ts`. It is a working engineering inventory to support a privacy policy and data-retention schedule — it is not itself a public-facing policy. Anything the code did not make clear is marked **VERIFY**.

Last reviewed against the codebase on the date this file was generated by an automated audit.

## 2. Under-13 parent-controlled accounts

Governed by `supabase/functions/parent-consent/index.ts`, behind feature switch `under13_parent_program`.

| Data | Where stored | Why collected | Shared with outside service | Proposed retention |
|---|---|---|---|---|
| Parent full name, relationship, parent birthdate, parent email, typed name, consent signature (PNG), IP, user agent | `parent_consents` (signature image file stored separately — **VERIFY storage bucket for `signature_path`**) | COPPA-style verifiable parental consent before an under-13 account can train | Stripe (parent's payment to confirm an adult is paying/controlling account); Resend (email to parent) | Consent records kept **3 years after the child's account ends** (not deleted on withdrawal — kept as proof of consent/withdrawal) |
| Consent/notice legal text shown to parent | `consent_texts` (versioned `parent_promise` / `parent_notice`) | Legal record of what the parent agreed to, by version | Not shared | Indefinite (legal text itself, not personal data) |
| Record of child-data deletion ("removed" JSON of what was wiped) | `child_data_deletions` | Proof that a parent's deletion request was honored | Not shared | Kept indefinitely as compliance evidence (contains no personal data beyond child_user_id reference) |
| Optional "training_opt_in" / "optional_sharing" flags | `parent_consents.training_opt_in`, `.optional_sharing` | Separate opt-in (off by default) for e.g. anonymized training-data use or optional outside sharing (e.g. PitchLab — see §6) | Only if opted in | Tied to consent record retention above |
| Child's own account row (locked until signed+paid) | `profiles` (`parent_controlled`, `parent_consent_ok`), gated by DB trigger `guard_profile_age_fields` | Enforce parent control, auto-pause under-13 accounts without consent | Not shared | Per account record above |

On "delete my child's data," the edge function wipes a defined list of tables but explicitly **keeps** `profiles` (the account row), `parent_consents`, `child_data_deletions`, and the parent-signature file as consent/deletion proof (`KEPT_ON_DELETE` constant, `supabase/functions/parent-consent/index.ts`).

In-app consent-notice text (`consent_texts`, kind=`parent_notice`, v1) itself states to parents: data is shared with "Google AI and OpenAI (only to produce the analysis; never to train their models), Stripe (your card payment), Resend (emails to you), and our hosting provider," that the child is hidden from scouts/recruiters/search/leaderboards, cannot message adults, and that optional sharing (e.g., PitchLab) requires a separate opt-in, off by default. This matches the vendor list independently found in code (§9).

| Data | Where stored | Why collected | Shared with outside service | Proposed retention |
|---|---|---|---|---|
| Pseudonymous id (`pid`), age band, role, sport, season phase, readiness band, training-age band, movement slug, dose/measures/rules/outcome JSON, week-over-week deltas | `anon_training_records` | Build and improve training-prescription models across the user base without storing identity | Not sent to any third party found in code; computed/stored entirely in Supabase | Indefinite, but only in de-identified/bucketed form (see mechanism below) |
| HMAC key used to pseudonymize user id into `pid` | Supabase Vault secret `anon_training_hmac_key` (generated via `vault.create_secret`, never exposed to clients) (`supabase/migrations/20261006202040_...sql`) | One-way, keyed hash of `auth.uid()` so records cannot be reversed to a user without the secret key | Not shared | Key itself retained as long as the anonymization scheme is in use; rotating it would sever linkage to past records |

Under-13 accounts are explicitly blocked from contributing to behavior-pattern tables (`block_under13_patterns()` trigger on `user_behavior_patterns`), and a child's record is only added to the anonymous training store if the parent separately opts in via `training_opt_in` (§2). **VERIFY** whether `anon_training_records` has an equivalent hard block for under-13 pids, beyond the opt-in gate, since the HMAC makes direct inspection difficult.

## 14. Vendors confirmed in code (summary)

1. **Lovable Cloud (Supabase)** — hosting, database, auth, storage, edge functions, for all data in this document.
2. **Google AI Studio (Gemini)** — primary AI provider for all video/text/image coaching analysis and chat, called directly (not via the Lovable AI Gateway) from `supabase/functions/_shared/googleAi.ts`.
3. **OpenAI** — documented fallback provider behind the same shared client.
4. **Stripe** — all payment processing, subscriptions, checkout, parent-consent billing.
5. **Resend** — all transactional email (guardian notices, problem reports, recaps, recruiting matches, cancellation feedback, idea submissions).
6. **Roboflow** — hosted computer-vision inference for pitch-velocity ball detection (frame images only).
7. **National Weather Service / Open-Meteo / Zippopotam.us / Nominatim (OpenStreetMap)** — weather, air quality, and geocoding lookups by coordinate or zip code.

No evidence of: Lovable AI Gateway being used at runtime (explicitly disclaimed in code comments), PitchLab integration (referenced only as a hypothetical future optional-sharing example in consent text), analytics/ad-tracking SDKs, native mobile push notification services, or any other outside vendor.
