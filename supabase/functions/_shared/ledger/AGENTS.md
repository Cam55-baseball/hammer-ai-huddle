- Client measurement saves use only `ledger-save` → `ledger_save`, judged by `_shared/ledger/saveRules.ts`; keys from `_shared/ledger/metricDictionary.ts`. Why: one ledger, one judge.
- Measurement readers keep their own queries and swap numbers only via `_shared/ledger/ledgerRead.ts` → `ledger_project_rows` under `ledger_unify_v1`; backfilled history is `legacy_hidden`. Why: the read path and parity check share one mapping, and old screens stay unchanged while the switch is off.
- Physically impossible values (`physics_ok = false`) read as unknown: `ledger_project_row` skips them, and stored legacy copies are parked in a private `_snapshot_*` before-state table, never deleted outright. Why: one bad entry must not reach any display, baseline or plan input, yet stays auditable.
- Typed measurement inputs ask `src/lib/ledger/entryCheck.ts` (dictionary bounds with unit conversion) and `saveRules.ts` rejects the same out-of-range values server-side; test-dependent legacy names resolve via `six_week.<test_type>.<base>` aliases (`sixWeekAlias`). Why: screens and the save path must agree, and one old name must not mean two metrics.
